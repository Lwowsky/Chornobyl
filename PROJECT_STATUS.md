## Зафіксовані правила

- Основний інтерфейс: верхній HUD + центральний контент + нижня навігація.
- Профіль не має кнопки в нижньому меню; відкривається натисканням на аватар у верхньому HUD.
- Профіль має одну й ту саму композицію на Desktop / Tablet / Mobile. На менших екранах вона стискається, але не перебудовується в інший дизайн.
- Базовий profile dialog: фіксований `520×760 px`. На менших viewport масштабується тільки весь dialog одним коефіцієнтом; внутрішня геометрія не перебудовується.
- Фон гри за профілем сильно розмивається та затемнюється.
- Блок `нік / рівень / бойова міць` усередині профілю прибраний: ця інформація вже є у верхньому HUD.
- Герой завжди по центру.
- Ліворуч від героя 5 слотів: Голова / Маска / Тіло / Плащ / Рукавиці.
- Праворуч 5 слотів: Штани / Взуття / Талісман / Артефакт / Дозиметр.
- Рюкзак як слот профілю не використовуємо.
- Ближню та дальню зброю прибрано з бокових колонок.
- Усередині нижньої частини фото героя розташовано 3 бойові слоти: `Ближня зброя / Дальня зброя / Набої`.
- Слоти ближньої та дальньої зброї мають той самий розмір, що й основні слоти екіпіровки; слот набоїв навмисно менший.
- Набої в майбутньому матимуть тип/рідкість і можуть давати бонуси, наприклад до атаки та криту. Механіку поки не підключаємо.
- Унизу профілю залишається компактне `Зведення характеристик` у дві колонки.
- Майбутній герой/екіпіровка використовують одну координатну систему. Робоче полотно: `768×1024`, master-render: `1536×2048`.
- Майбутня сітка героя: `96×128`.
- Не використовувати `!important`.
- `css/styles.css` — тільки глобальні стилі/reset.
- Кольори, шрифти, розміри та design tokens — у `css/core/variables.css`.
- Responsive CSS — окремо mobile / mobile-small / tablet / desktop.
- UI-тексти готувати через i18n; зараз активна тільки українська.

## v0.07 — Uniform Profile Scaling Fix
- Виправлено головну проблему mobile/responsive профілю: фіксований дизайн `520×760` більше не намагається жити у viewport як нескейлений 520px layout.
- Додано `profile-stage`, який займає вже фактичний візуальний розмір масштабованого профілю. Сам `profile-dialog` залишається логічно рівно `520×760` і масштабується лише цілком.
- Масштаб тепер обчислюється одним коефіцієнтом: `min(1, доступна ширина / 520, доступна висота / 760)`. Ширина і висота ніколи не змінюються незалежно одна від одної.
- На великих/середніх екранах, де `520×760` влазить, профіль завжди має однаковий розмір. На меншому екрані весь профіль пропорційно зменшується так, щоб повністю влазити і по ширині, і по висоті без внутрішнього scroll.
- Для мобільних браузерів використовується `visualViewport`, тому масштаб враховує реальну видиму висоту після browser UI / DevTools viewport.
- Прибрано попередній мінімальний clamp `0.5`, який міг залишати профіль більшим за дуже вузький viewport.
- Responsive CSS як і раніше не містить окремої геометрії профілю.
- Структура слотів, hero-frame та нижнє зведення характеристик не перебудовувалися.

### Зафіксоване responsive-правило
Профіль — це фіксований canvas `520×760`. Не змінювати окремо його width/height через media queries. Якщо він не влазить — масштабувати весь canvas одним коефіцієнтом через `profile-stage`. Внутрішній scroll для вкладки Герой не використовувати.

- Верхній HUD більше не перебудовується занадто рано. Макет `гравець | ресурси | гроші` тепер зберігається до ширини `430px`.
- Для діапазону `430–767px` HUD залишається трьохколонковим, але з компактнішими пропорціями: картка героя, блок ресурсів і збільшений блок грошей.
- Блок ресурсів у діапазоні `430–767px` залишається всередині верхнього ряду, як на більших екранах; дрібно зменшені внутрішні відступи, іконки та шрифти, щоб усе вміщалося без перенесення вниз.
- Лише нижче `430px` HUD переходить у дворядний mobile-режим. У цьому режимі верхній ряд використовує співвідношення `65/35` між карткою героя і грошима, а блок ресурсів стає другим рядом.
- Базові mobile-стилі `game-shell`, `world-screen` та карток локації залишені спільними для всіх екранів до `767px`; breakpoint для перебудови самого HUD відокремлено від інших mobile-правил.
- `!important` не використовується.


## v0.12 — HUD medium-screen reflow

- У діапазоні `430–699px` верхній ряд тепер складається лише з двох блоків: `профіль` (фіксовано 190px) і `гроші` (займають решту ширини).

## v0.13 — HUD money row swap
- На великих і середніх широких екранах верхній HUD перебудовано: тепер перший ряд складається з `профіль + 4 ресурси`, а блок грошей перенесено в окремий нижній ряд.
- Для desktop використовується двоколонкова схема `300px + 1fr`, для tablet / 700–767px — компактний варіант `250px/210px + 1fr`, без великої порожньої панелі грошей праворуч.
- Поточний layout `профіль + гроші зверху, ресурси другим рядом` збережено лише для вузьких екранів, де широкий ряд уже не вміщується (`430–699px` і `<430px`).
- Логіка адаптації тепер така: `>=700px` — гроші знизу; `<700px` — гроші праворуч угорі, ресурси другим рядком.
- Внутрішні стилі карток ресурсів не дубльовано, `!important` не використовується.


## v0.14 — HUD threshold rollback

- Лише для `429px і менше` збережено окремий mobile-режим: верхній ряд `профіль + гроші`, другий ряд `ресурси`.
- Для `430–529px` і `530–767px` додано окремі компактні налаштування ширини профілю, блоку грошей і resource-card, щоб layout не ламався так рано.

## v0.15 — HUD responsive cleanup
- Виправлено проблему, що накопичилась у v0.11–v0.14: геометрія HUD була розмазана по кількох media-query і постійно перевизначала сама себе. Це не були точні копії одного правила, але фактично було дублювання responsive-логіки.
- Тепер для `430px+` є одне базове правило: `профіль | ресурси | гроші` в одному рядку.
- Для `430–699px` існує лише один компактний override внутрішніх розмірів, без перестановки блоків.
- Єдина реальна перебудова layout відбувається на `429px і нижче`: `профіль + гроші` у першому рядку, `4 ресурси` у другому.
- Межа `429/430` тепер задається через явні `grid-column/grid-row`, без `grid-template-areas`, щоб уникнути стрибків/накладань на межі breakpoint.
- Tablet більше не дублює геометрію HUD. Desktop змінює лише візуальні розміри/відступи, а не структуру колонок.
- `!important` не використовується.


## v0.16 — HUD 429/430 boundary fix
- Виправлено останній граничний баг між `429px` і `430px`: Chrome DevTools може показувати округлене значення `429`, тоді як фактична CSS-ширина viewport трохи більша за 429px. Через це старий `max-width: 429px` інколи не спрацьовував.
- Mobile breakpoint змінено на `max-width: 429.98px`, тому всі фактичні ширини нижче 430px гарантовано переходять у дворядний HUD.
- При `430px` і вище структура не змінюється: `профіль | ресурси | гроші` лишаються в одному рядку.
- При ширині нижче 430px: `профіль + гроші` у першому рядку, `4 ресурси` у другому.
- Жодних нових responsive-блоків не додано; змінено тільки межу існуючого mobile media query.
- `!important` не використовується.
